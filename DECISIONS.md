# DECISIONS.md

Architecture and design decisions made during development. Append-only — do not edit prior entries.

---

| Date | Decision | Rationale | Implications |
|---|---|---|---|
| 2026-04-02 | Use DuckDB as the panel database instead of flat CSV | Need longitudinal panel with quarterly snapshots, entity resolution across time, and SQL query support for researchers. CSVs can't handle this at scale. | `bbrt.duckdb` is the source of truth; `businesses.csv` is an export layer for the public site only. |
| 2026-04-02 | Use Census Geocoder batch API instead of Nominatim/OSM | Free, no API key, no rate limit, up to 10,000 addresses per request, and specifically designed for U.S. addresses. Original V1 used Nominatim. | Only geocode new records each quarter — already-geocoded businesses are not re-processed. |
| 2026-04-02 | Adapter pattern with `AdapterBase` abstract class | Each state source has different formats/APIs; need to isolate breakage, enable independent development, and allow auto-discovery by the orchestrator. | Adding a new source = one new file in `scripts/adapters/`. Orchestrator requires no changes. |
| 2026-04-02 | Store all source fields in `source_fields` JSON column | Don't discard data — sources often have fields with no BBRT equivalent that may be valuable for researchers. Promotes fields to standard columns when they appear across many sources. | Keeps schema stable while preserving raw data. Field catalog table (`field_catalog`) documents coverage. |
| 2026-04-02 | Two confidence tiers: `confirmed_black` vs `mbe_unverified` | Some sources (SAM.gov 8(a)) only identify "MBE" with no ethnicity breakdown. Including them expands coverage but risks diluting the dataset if not clearly labeled. | All records must carry a `confidence` field. Site V2 will display this as a badge. Researchers can filter by tier. |
| 2026-04-02 | GitHub Actions quarterly cron at `0 6 1 1,4,7,10 *` | Pipeline needs to be fully automated with no manual triggering. GitHub Actions is free for public repos, integrates with git push, and sends failure notifications. | Next auto-run: 2026-07-01. Manual runs can be triggered via `workflow_dispatch`. |
| 2026-04-02 | Site V1 remains static HTML/JS (no framework, no build process) | Simplicity, zero hosting cost (GitHub Pages), no CI/CD complexity. The data is the product, not the UI framework. | Fine for current scale. Site V2 adds state/city dropdowns but stays static — reads `businesses.csv` dynamically via PapaParse. |
| 2026-04-03 | `sam_8a` adapter built but excluded from 2026-Q2 baseline | SAM_GOV_API_KEY not yet configured as a GitHub Actions secret. Adapter is correct and tested; it was a deployment blocker, not a code issue. | Must add `SAM_GOV_API_KEY` to GitHub repo secrets before next quarterly run (2026-07-01). |
| 2026-06-10 | Expansion prioritizes auto-fetch (API/URL) sources; hand-download sources become manual-refresh | A clean-environment audit found 5 of 7 existing adapters read manually-downloaded Excel/CSV files from local disk/Dropbox — unrunnable in the GitHub Actions cron. The national inventory confirmed the genuinely autonomous `confirmed_black` sources are API/URL-based (CT, DE via Socrata; OR, NV, SC via direct Excel URLs). The "don't-touch-it" goal requires building on those. | Phase 2 big push + the weekly agent build ONLY auto-fetching sources. File-based sources (md_mbe, ma_sdo, in_idoa, and blocked gob2g/portal directories) refresh only when Kyle provides a file. |
| 2026-06-10 | Pipeline carries forward sources that don't run in a cycle instead of dropping them | The cron runs in a clean environment with no manual files; the old "skip failed source, write snapshot without it" behavior dropped whole states (reproduced locally: 13,948 → 7,946), recording false business exits and corrupting entry/exit tracking — fatal for a longitudinal panel used for survival analysis. | New `carry_forward_records()` re-inserts an un-run source's latest rows into the new snapshot; registry `is_active`/`last_seen` left untouched. `snapshots.sources_carried_forward` records which sources were stale each quarter. A real exit is only recorded when a source DID run and the business is gone. |
| 2026-06-10 | SAM.gov 8(a) adapter blocked by API access, not key config | With the data.gov key set, both v3 and v4 SAM.gov entity endpoints return 404 — the entity-extract API needs a SAM.gov system account/role, not a personal data.gov key. | `sam_8a` remains unloaded; needs SAM.gov system-account investigation. Tracked in `sources_roadmap.yml`. Not a blocker for the auto-fetch big push. |
| 2026-06-10 | Indiana data not in DB; current Dropbox source file is empty | The `in_idoa` adapter reads a local Dropbox `certification_list.xlsx` that is now empty (1 row); the original 4,759 records came from a populated version no longer present. | Indiana stays absent until Kyle re-exports a populated file. Per the auto-fetch decision, Indiana is a manual-refresh source. |
| 2026-06-12 | Skip sources that lack a per-firm Black/ethnicity field — confirmed_black only | The database's core value is that every record is verifiably Black-owned. DBE/minority directories without an ethnicity column (TN, UT, ID, NM, OK, WA, and most state DOT DBE programs) cannot identify Black firms — they lump together women-owned and all minority groups (Nevada's directory was only ~16% Black). Loading them as `mbe_unverified` would add mostly-non-Black firms and dilute the dataset. | Standing policy: do NOT load a source unless it has a usable Black/ethnicity field. Such sources are marked `blocked` with reason "no ethnicity field" in the roadmap and are not retried. The `mbe_unverified` tier is reserved for sources with a real minority/disadvantage signal worth flagging (e.g., SAM 8(a)), not race-blind DBE rosters. |
